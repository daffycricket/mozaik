Remarques : cause de l'instabilité : le test de pan fusionnait les intervalles des 3 exécutions avant d'en prendre le maximum, donc le pic isolé d'un seul run (411 ms, sans tâche longue associée) suffisait à échouer F02-S1-AC4. Le correctif applique la méthode de F00 (« médiane des 3 exécutions ») : chaque run produit sa médiane et son maximum, et la valeur retenue est la médiane des trois (`tooling/fluidity-stats.ts`, `frameStatsPerRun` / `medianOfMaxima`). Les seuils (médiane ≤ 33 ms, maximum ≤ 200 ms, tâche longue ≤ 200 ms) et les assertions sont inchangés ; deux runs instables sur trois échouent toujours (test unitaire `[B-001-AC1]`). `e2e/fluidity/board-pan.spec.ts` a été enchaîné 10 fois de suite (`--repeat-each=10`) puis 6 fois avec 6 cœurs saturés : aucun échec. Docker : non vérifié (absent de l'environnement). Aucune exclusion de couverture ajoutée. Test hérité modifié (voir journal `test`).
