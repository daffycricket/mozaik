## Étapes

### Étape 1 : page « Board introuvable » sur un board inexistant

- Critères d'acceptance couverts : F01-S5-AC1, UI-ERR-1
- Code applicatif :
  - `apps/web/src/lib/boards-api.ts` : `BoardNotFoundError` levée sur `404` par `getBoard`, pour distinguer l'absence du board d'une autre erreur.
  - `apps/web/src/app/board-page.tsx` : lecture du board avant la garde d'identité ; tant que la lecture n'a pas abouti, rien n'est affiché (ni dialogue de nom, ni connexion) ; si le board est introuvable, rendu de `BoardNotFound` ; sinon, garde d'identité puis `BoardView`, qui reçoit le nom déjà lu.
  - `apps/web/src/app/board-not-found.tsx` : composant `BoardNotFound` (titre, explication, bouton `nav-boards`), centré horizontalement et verticalement.
- Code technique : aucun : la vérification de l'existence s'appuie sur la route `GET /api/boards/:id` déjà livrée par F01-S2.
- Code de test :
  - Unitaire : `apps/web/src/lib/boards-api.test.ts` (erreur typée sur 404), `apps/web/src/app/board-page.test.tsx` (rendu de `BoardNotFound`), `apps/web/src/app/pages.test.tsx` (le board n'est plus rendu synchronement ; la garde d'identité et l'absence de canvas restent vérifiées).
  - E2E : `e2e/board-not-found.spec.ts` (F01-S5-AC1 : page affichée, pas de dialogue de nom, aucune WebSocket, lien vers le menu).
  - Layout : `e2e/layout/board-not-found.spec.ts` (UI-ERR-1 aux viewports 1280 × 800 et 1024 × 768).
- Documentation et Markdown : `docs/journal.md` (décisions : lecture avant garde d'identité, traitement des erreurs non-404, tests hérités adaptés), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F01-S5.md` (étape 1).
- Terminée quand : `pnpm verify` est vert (y compris `ac:check` sur F01-S5-AC1 et UI-ERR-1), `/b/inexistant` affiche la page centrée sans dialogue de nom ni WebSocket, et un board existant s'ouvre comme avant.
