## Étapes

### Étape 1 : Squelette du monorepo et configuration partagée

- Critères d'acceptance couverts : T-001-AC1, T-001-AC3, T-001-AC5, T-001-AC6
- Code applicatif : `packages/model/src/index.ts` (constante de version du modèle, préfiguration du paquet partagé).
- Code technique : `package.json` racine (`packageManager`, `engines.node`, scripts `lint`, `typecheck`, `test:unit`, `verify`, `dev`), `pnpm-workspace.yaml`, `packages/config` (`package.json`, `tsconfig.base.json` strict, `biome.json`), `tsconfig.json` racine pour l'outillage, `biome.json` racine (overrides d'imports restreints), `vitest.config.ts`, `apps/web` et `apps/server` (manifestes et tsconfig).
- Code de test : `tooling/workspace.test.ts` (`[T-001-AC1]`), `tooling/quality-controls.test.ts` (`[T-001-AC3]`, `[T-001-AC6]` : exécute `tsc` et `biome` sur des fixtures valides/invalides), `packages/model/src/index.test.ts` (`[T-001-AC5]`), `packages/config/src/config.test.ts` (`[T-001-AC5]`).
- Documentation et Markdown : `docs/plans/T-001.md` (journal si évolution), `docs/journal.md` (entrées `dépendance`).
- Terminée quand : `pnpm install`, `pnpm lint`, `pnpm typecheck` et `pnpm test:unit` passent, et les fixtures invalides font échouer les outils.

### Étape 2 : Serveur health, front React/Vite et `pnpm dev`

- Critères d'acceptance couverts : T-001-AC2, T-001-AC5
- Code applicatif : `apps/server/src/app.ts` (fabrique Fastify + route health), `apps/server/src/index.ts` (écoute sur `PORT`), `apps/web/index.html`, `apps/web/src/main.tsx`, `apps/web/src/app.tsx` (nom de l'application).
- Code technique : `apps/web/vite.config.ts` (plugin React, alias `@`, proxy `/api`), scripts `dev` par app et à la racine.
- Code de test : `apps/server/src/app.test.ts` (`[T-001-AC2]`, `[T-001-AC5]` : `fastify.inject`), `apps/web/src/app.test.tsx` (`[T-001-AC2]`, `[T-001-AC5]` : `renderToStaticMarkup`).
- Documentation et Markdown : `docs/architecture.md` si la structure réelle diverge de la cible.
- Terminée quand : `pnpm dev` démarre le serveur (health 200) et le front, et `pnpm verify` est vert.

### Étape 3 : Hook `commit-msg` et validateur

- Critères d'acceptance couverts : T-001-AC4, T-001-AC5
- Code applicatif : aucun : outillage uniquement.
- Code technique : `tooling/commit-msg.ts` (validateur + CLI), `simple-git-hooks` dans `package.json` avec `prepare`.
- Code de test : `tooling/commit-msg.test.ts` (`[T-001-AC4]` : cas acceptés et refusés, `[T-001-AC5]`).
- Documentation et Markdown : `docs/architecture.md` (ajout de `tooling/`), `docs/journal.md` (`dépendance`, `décision` sur le validateur), `docs/backlog.md` (T-001 `done`).
- Terminée quand : un commit d'étape conforme passe le hook et un message non conforme est refusé ; `pnpm verify` est vert.
