## Étapes

### Étape 1 : ouvrir un board de 300 éléments mélangés

- Critères d'acceptance couverts : F02-S3-AC1
- Code applicatif : aucun : la story ne change pas le rendu du board, seulement la fixture de test et sa vérification.
- Code technique :
  - `apps/server/src/app.ts` : l'option `mixed` du schéma de `POST /api/test/seed` ; `seedDocument` alterne les types `sticky`, `rect`, `ellipse`, `text`, `arrow` quand `mixed` est vrai (comportement actuel conservé sinon, pour ne pas toucher aux tests hérités).
- Code de test :
  - E2E : `e2e/fluidity/board-open.spec.ts` (`[F02-S3-AC1]`), qui sème un board de 300 éléments mélangés, ouvre le board depuis le menu, vérifie les 300 éléments et la présence des cinq types, et mesure FL-7 (ouverture ≤ 3 s) et FL-3 (aucune tâche longue > 200 ms).
- Documentation et Markdown : `docs/architecture.md` (signature de `POST /api/test/seed`), `docs/journal.md` (décision sur l'option `mixed`), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F02-S3.md` (étape 1).
- Terminée quand : `pnpm verify` est vert (y compris `ac:check` sur F02-S3-AC1), le board de 300 éléments mélangés expose bien ses 300 éléments dans `window.__board.getElements()` à l'ouverture, et les mesures FL-3 et FL-7 sont dans les seuils de F00.
