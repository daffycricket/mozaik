# Plan : B-003 Mesure FL-2 du redimensionnement instable sous charge (annulation partielle)

- Ticket : [backlog](../backlog.md), détail [B-003](../backlog.md#b-003--redimensionnement--annulation-partielle-sous-charge)
- Critères d'acceptance visés : B-003-AC1
- Branche : `bug/B-003-atomic-gesture-undo`

## Contexte

La vérification indépendante de `main` après F06-S2 (`logs/verify-031.log`) a échoué : le test `[F07-S3-AC4]` (`e2e/fluidity/board-resize.spec.ts`) a dépassé son délai en attendant que la largeur revienne à sa valeur d'origine après un seul `Ctrl+Z` (attendu 100, reçu 124). Reproduit hors ligne : un `Ctrl+Z` ne restaure qu'une partie du redimensionnement.

Cause racine : un geste de glisser écrit dans Yjs plusieurs fois (au plus toutes les 50 ms). Le `Y.UndoManager` fusionne ces écritures en une seule entrée tant qu'elles sont séparées de moins que son `captureTimeout` (500 ms par défaut). Quand le fil principal se bloque plus de 500 ms entre deux écritures (charge machine, encodage vidéo, GC — ce qui arrive sur un board de 300 éléments), le geste est scindé en plusieurs entrées et un seul `Ctrl+Z` n'annule que la dernière partie. Vérifié par un test unitaire qui force cet écart : sans correctif, `undo` laisse une valeur intermédiaire.

## Étapes

### Étape 1 : un geste de glisser est toujours une seule entrée d'annulation

- Critères d'acceptance couverts : B-003-AC1
- Code applicatif :
  - `packages/model/src/history.ts` : `HISTORY_CAPTURE_TIMEOUT_MS` (500 ms, défaut) et `HISTORY_GESTURE_TIMEOUT_MS` (60 s) ; `beginHistoryGesture(history)` ouvre une entrée atomique (fenêtre de fusion large + `stopCapturing`), `endHistoryGesture(history)` la referme et restaure la fenêtre par défaut.
  - `apps/web/src/canvas/use-select.ts` : les débuts/fins de geste (déplacement, redimensionnement, glisser d'extrémité de flèche) utilisent `beginHistoryGesture`/`endHistoryGesture` à la place de `stopCapturing()`.
- Code technique : aucun : la propriété publique `captureTimeout` du `Y.UndoManager` suffit.
- Code de test :
  - Unitaire : `packages/model/src/history.test.ts`, nouveau bloc `[B-003-AC1]` : (1) un geste contenant un écart de 600 ms entre deux écritures est annulé d'un seul `undo` ; (2) deux gestes séparés par les bornes restent deux entrées. Les cas existants ne sont pas modifiés (seuls des imports sont ajoutés).
  - E2E : `e2e/fluidity/board-resize.spec.ts` (existant, `[F07-S3-AC4]`) sert de vérification de non-régression : la boucle `Ctrl+Z` de la ligne 142 ne doit plus échouer sous charge. Aucune modification du test, aucun seuil abaissé, aucun `skip`.
- Documentation et Markdown : `docs/backlog.md` (B-003 ajouté puis `done`), `docs/journal.md` (décision + test), rapport `docs/test-reports/B-003.md` (étape 1). `docs/architecture.md` n'est pas modifié : le comportement décrit (une entrée d'annulation par geste) était déjà la règle annoncée, ce ticket la rend vraie.
- Terminée quand : `pnpm verify` est vert, y compris `ac:check` sur B-003-AC1 ; un geste de glisser reste une seule entrée d'annulation même si le fil principal se bloque plus de 500 ms entre deux écritures ; `e2e/fluidity/board-resize.spec.ts` enchaîné plusieurs fois de suite ne fait plus échouer la vérification d'annulation (ligne 142).
