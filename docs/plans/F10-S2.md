## Étapes

### Étape 1 : Afficher les curseurs distants nommés et colorés

- Critères d'acceptance couverts : F10-S2-AC1, F10-S2-AC2, F10-S2-AC3, F10-S2-AC4, F10-S2-AC5, UI-BOARD-12
- Code applicatif :
  - `packages/model/src/presence.ts` : palette de 12 couleurs utilisateur, couleur déterministe par identifiant, schémas zod de `PresenceState`, validation, visibilité d'un point, interpolation d'un point.
  - `apps/web/src/collab/presence-context.ts` : contexte du provider et de l'identité.
  - `apps/web/src/collab/use-local-cursor.ts` : publication du curseur local dans l'awareness, au plus toutes les 50 ms.
  - `apps/web/src/canvas/remote-cursors.tsx` : abonnement à l'awareness, interpolation et rendu Konva (flèche + étiquette de couleur).
  - `apps/web/src/canvas/board-canvas.tsx` : branchement de la publication et du rendu des curseurs.
  - `apps/web/src/app/board-page.tsx` : transmission de l'identité à la vue board et du provider au contexte de présence.
  - `apps/web/src/testing/board-api.ts` : `getOverlayBoxes()` renvoie les curseurs distants visibles à l'écran.
- Code technique : aucun.
- Code de test :
  - Unitaire : `packages/model/src/presence.test.ts` (palette, couleur, validation, visibilité, interpolation) ; `apps/web/src/testing/board-api.test.ts` (curseurs distants et filtrage hors écran) ; `apps/web/src/lib/theme-tokens.test.ts` (jeton du label, déjà générique).
  - E2e : `e2e/presence.spec.ts` (AC1, AC3, AC4, AC5) ; `e2e/fluidity/presence.spec.ts` (AC2, FL-4) ; `e2e/layout/board-cursor.spec.ts` (UI-BOARD-12).
- Documentation et Markdown : `docs/design/charte.md` (jeton `--cursor-label-text`), `docs/design/composants.md` si besoin, `docs/journal.md` (décisions : palette, interpolation, visibilité), `docs/test-reports/F10-S2.md`.
- Terminée quand : deux navigateurs voient le curseur nommé et coloré de l'autre, hors écran il disparaît, il disparaît au départ, l'interpolation est fluide (FL-4) et `pnpm verify` est vert.
