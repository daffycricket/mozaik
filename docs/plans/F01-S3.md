## Étapes

### Étape 1 : renommer un board depuis l'en-tête

- Critères d'acceptance couverts : F01-S3-AC1, F01-S3-AC2, F01-S3-AC3, UI-BOARD-11
- Code applicatif :
  - `apps/server/src/db/boards.ts` : `renameBoard` (met à jour `name` et `updated_at`, `null` si inconnu).
  - `apps/server/src/http/boards.ts` : `PATCH /api/boards/:id` (400 nom invalide, 404 board inconnu, 200 board).
  - `apps/web/src/lib/boards-api.ts` : `renameBoard` et `validateBoardName` (nom découpé, 1 à 100 caractères).
  - `apps/web/src/app/board-name.tsx` : composant `BoardName` : bouton `board-name` au clic, champ `board-name-input` (Entrée valide, Échap annule, perte de focus annule).
  - `apps/web/src/app/board-page.tsx` : `BoardShell` rend `BoardName`, `BoardScreen` / `BoardPage` transmettent le renommage et mettent à jour l'état du board lu.
- Code technique : aucun : le harnais de test et la config existent déjà.
- Code de test :
  - Unitaire : `apps/server/src/db/boards.test.ts` (renommage, board inconnu), `apps/web/src/lib/boards-api.test.ts` (`renameBoard`, `validateBoardName`), `apps/web/src/app/board-page.test.tsx` (test hérité adapté au nouveau contrat `onRename`).
  - Intégration : `apps/server/test/boards.int.test.ts` (`PATCH` : renommage, découpage des espaces, 400 nom vide, 404 board inconnu).
  - E2E : `e2e/board-rename.spec.ts` (F01-S3-AC1 à AC3), `e2e/layout/board-name.spec.ts` (UI-BOARD-11).
- Documentation et Markdown : `docs/journal.md` (décision sur l'annulation par perte de focus et modification du test hérité), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F01-S3.md` (étape 1). `docs/architecture.md` documente déjà `PATCH /api/boards/:id`.
- Terminée quand : `pnpm verify` est vert (y compris `ac:check` sur F01-S3-AC1 à AC3 et UI-BOARD-11), le renommage depuis l'en-tête se voit dans l'en-tête et sur le menu, Échap conserve l'ancien nom, un nom vide ne déclenche aucun `PATCH`.
