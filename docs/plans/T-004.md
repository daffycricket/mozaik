## Étapes

### Étape 1 : harnais de mesure de la fluidité

- Critères d'acceptance couverts : T-004-AC1, T-004-AC2, T-004-AC3, T-004-AC4, T-004-AC5, T-004-AC6
- Code applicatif : aucun : T-004 est un ticket technique de test, il ne modifie pas l'application.
- Code technique :
  - `e2e/support/probe.ts` : instrumente la page (`addInitScript`) pour enregistrer les horodatages `requestAnimationFrame` et les tâches longues (`PerformanceObserver`, `longtask`), puis calcule médiane et maximum des intervalles (T-004-AC1, T-004-AC2).
  - `e2e/support/websocket-latency.ts` : `addWebSocketLatency(page, ms)` intercepte le WebSocket de collaboration via `page.routeWebSocket`, applique un `setTimeout` dans les deux sens et compte les messages transmis (T-004-AC3).
  - `e2e/support/action-effect.ts` : `measureActionToEffect(page, action, effect)` (horloge de la page observatrice) et `countIntermediatePositions(positions)` (T-004-AC4).
  - `e2e/support/fluidity-report.ts` : `recordFluidityMeasure` écrit `test-results/fluidity.json` (ignoré par Git) et `videoPathFor(testInfo)` donne le chemin de la vidéo (T-004-AC5).
  - `playwright.config.ts` : second projet `fluidity` (`testMatch` sur `e2e/fluidity/`, `video: 'on'`), le projet `chromium` ignore ces specs (T-004-AC5).
  - `tooling/report.ts` : lit `test-results/fluidity.json` et ajoute au rapport un tableau « Exigence | Scénario | Mesure | Seuil | Vidéo » (T-004-AC5).
- Code de test :
  - E2E : `e2e/fluidity/utilities.spec.ts` (intervalles d'images, tâches longues, latence WebSocket bidirectionnelle, action → effet local et distant, comptage des positions) et `e2e/fluidity/empty-board.spec.ts` (FL-7 : ouverture d'un board vide en ≤ 1 s, médiane de 3 exécutions, mesure consignée).
  - Unitaire : `tooling/report.test.ts` (lecture du JSON de fluidité et rendu du tableau).
- Documentation et Markdown : `docs/features/F00-fluidite.md` (historique des seuils si calibration), `docs/journal.md` (décisions), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/T-004.md` (étape 1).
- Terminée quand : `pnpm verify` est vert (les deux projets Playwright passent), `pnpm report T-004 --step 1` produit le tableau de fluidité et les seuils sont consignés.
