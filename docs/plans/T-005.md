## Étapes

### Étape 1 : lancement local avec Docker Compose

- Critères d'acceptance couverts : T-005-AC1, T-005-AC2, T-005-AC3, T-005-AC4, T-005-AC5, T-005-AC6, T-005-AC7, T-005-AC8
- Code applicatif :
  - `apps/server/src/http/static.ts` : enregistrement de `@fastify/static` sur `STATIC_DIR` et repli `index.html` pour le routage côté client (T-005-AC2).
  - `apps/server/src/app.ts` : branchement du service statique quand `STATIC_DIR` est défini (T-005-AC2).
- Code technique :
  - `apps/server/package.json` : dépendance `@fastify/static` (MIT).
  - `Dockerfile` : image multi-étapes `node:24-slim`, build du front, exécution du serveur (T-005-AC1).
  - `docker-compose.yml` : service `app`, port `127.0.0.1:${MOZAIK_PORT:-8080}:3001`, volume nommé `board-data`, `DATABASE_PATH=/data/board.sqlite`, `STATIC_DIR`, healthcheck sur `/api/health` (T-005-AC1, AC3, AC4).
  - `.dockerignore` : contexte de build minimal.
  - `e2e-docker/playwright.config.ts` : projet Playwright dédié, `baseURL` issue de `MOZAIK_DOCKER_BASE_URL` (T-005-AC5).
  - `e2e-docker/support/compose.ts` : helpers `docker compose` (projet et port passés par l'environnement) (T-005-AC3, AC4).
  - `tooling/docker.ts` : `runDockerScenario` (up, attente du healthcheck, tests, `down -v` dans un `finally`) et détection de Docker (T-005-AC5).
  - `tooling/test-docker-cli.ts` : entrée de `pnpm test:docker` (T-005-AC5).
  - `tooling/verify.ts` et `tooling/verify-cli.ts` : plan de vérification conditionnel à la présence de Docker, avertissement sinon (T-005-AC6).
  - `tooling/report.ts` : `Docker : vérifié | non vérifié` d'après un marqueur écrit par `test:docker` (T-005-AC6).
  - `package.json` : script `test:docker`.
  - `README.md` : lancement Docker conforme à ce qui est livré (T-005-AC7).
  - `tsconfig.json` : inclut `e2e-docker`.
- Code de test :
  - Intégration : `apps/server/test/static.int.test.ts` (`[T-005-AC2]` : `index.html` pour `/b/<id>`, actifs servis, API inchangée).
  - E2E : `e2e/packaged.spec.ts` (`[T-005-AC8]` : construit le front, démarre le serveur avec `STATIC_DIR` sur un port libre, vérifie menu, URL `/b/<id>` directe et API).
  - E2E Docker : `e2e-docker/packaged.spec.ts` (`[T-005-AC1]`, `[T-005-AC2]`, `[T-005-AC3]`, `[T-005-AC4]`).
  - Unitaire : `tooling/docker.test.ts` (`[T-005-AC5]` nettoyage même en cas d'échec, `[T-005-AC6]` plan de vérification et statut Docker du rapport, `[T-005-AC7]` contenu du README).
- Documentation et Markdown : `docs/architecture.md` (si l'état du service statique le rend inexact), `docs/journal.md` (décisions, dépendances), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/T-005.md` (étape 1).
- Terminée quand : `pnpm verify` est vert ; `pnpm test:e2e` exerce le mode packagé sans Docker ; `pnpm test:docker` est branché (non exécuté sans Docker, « Docker : non vérifié ») ; les huit critères sont couverts par un test nommé.
