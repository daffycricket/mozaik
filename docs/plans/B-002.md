# Plan : B-002 Mesure FL-2 du zoom instable sous charge

- Ticket : [backlog](../backlog.md), détail [B-002](../backlog.md#b-002--mesure-fl-2-du-zoom-instable-sous-charge)
- Critères d'acceptance visés : B-002-AC1
- Branche : `bug/B-002-stable-zoom-frame-measure`

## Contexte

Le test `[F02-S2-AC4]` (`e2e/fluidity/board-zoom.spec.ts`) mesure FL-2 (intervalle médian ≤ 33 ms, aucun intervalle > 200 ms) sur trois exécutions du scénario, puis agrège les intervalles des trois runs en un seul ensemble : la médiane est stable, mais le maximum est celui de l'ensemble fusionné, donc le pic d'un seul run suffit à faire échouer le test. Le constat de B-002 (max 547 ms au run e2e complet, repassé isolément puis au run complet suivant) est identique à celui de B-001 pour le pan : un aléa de la machine (encodage vidéo, GC, charge), sans tâche longue associée, pas un gel applicatif.

F00 (`docs/features/F00-fluidite.md`, « Méthode de mesure ») impose déjà la parade : chaque mesure chiffrée est prise sur 3 exécutions et l'on retient la **médiane des 3**, précisément pour absorber le bruit de la machine sans retry. Le test du zoom ne l'applique qu'à la médiane, pas au maximum. B-001 a corrigé exactement ce défaut pour le pan en introduisant `frameStatsPerRun` et `medianOfMaxima` (`tooling/fluidity-stats.ts`). Ce ticket applique la même agrégation au test du zoom. Aucun seuil de F00 n'est abaissé, aucun test n'est marqué `skip`.

## Étapes

### Étape 1 : le pic d'un seul run n'échoue plus la mesure FL-2 du zoom

- Critères d'acceptance couverts : B-002-AC1
- Code applicatif : aucun : B-002 est un ticket de test, il ne modifie pas l'application.
- Code technique :
  - `e2e/fluidity/board-zoom.spec.ts` : collecte les intervalles et les tâches longues par run (`number[][]`) au lieu de les fusionner, puis utilise `frameStatsPerRun` et `medianOfMaxima` (déjà exportés par `e2e/support/probe.ts`). Les seuils (médiane ≤ 33 ms, maximum ≤ 200 ms, tâche longue ≤ 200 ms) et les assertions sont inchangés. Aucune nouvelle fonction dans `tooling/fluidity-stats.ts`, déjà couverte par B-001.
- Code de test :
  - Unitaire : cas `[B-002-AC1]` ajoutés à `tooling/fluidity-stats.test.ts` (nouveau bloc `describe`, sans retirer ni modifier les cas hérités) : (1) un run instable sur trois est absorbé pour le zoom (max retenu = celui des deux runs stables) ; (2) deux runs instables sur trois échouent encore (max retenu > 200 ms) ; (3) un pic de tâche longue isolé est absorbé par `medianOfMaxima`.
  - E2E : `e2e/fluidity/board-zoom.spec.ts` (`[F02-S2-AC4]`, hérité) est modifié pour l'agrégation par run, avec les mêmes seuils et assertions (aucun cas ni assertion retiré).
- Documentation et Markdown : `docs/backlog.md` (B-002 `in-progress` puis `done`), `docs/journal.md` (décision + test), rapport `docs/test-reports/B-002.md` (étape 1). `docs/features/F00-fluidite.md` n'est pas modifié : aucun seuil n'est ajusté.
- Terminée quand : `pnpm verify` est vert, y compris `ac:check` ; `e2e/fluidity/board-zoom.spec.ts` enchaîné plusieurs fois de suite ne fait plus échouer `[F02-S2-AC4]` sous charge, sans seuil abaissé ni `skip`.
