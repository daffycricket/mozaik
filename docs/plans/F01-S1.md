## Étapes

### Étape 1 : créer et ouvrir un board

- Critères d'acceptance couverts : F01-S1-AC1, F01-S1-AC2, F01-S1-AC3
- Code applicatif :
  - Serveur : `apps/server/src/http/boards.ts` (schéma zod du corps, handler `POST /api/boards`, enregistrement), `apps/server/src/http/errors.ts` (corps d'erreur partagé), `apps/server/src/app.ts` (montage des routes board).
  - Web : `apps/web/src/app/routes.ts` (type `Route`, `parsePath`, `navigate`), `apps/web/src/app/router.tsx` (hook `useRoute` via `useSyncExternalStore`), `apps/web/src/app/board-list-page.tsx` (bouton `board-create`), `apps/web/src/app/board-page.tsx` (conteneur `board-canvas` vide), `apps/web/src/lib/boards-api.ts` (client `createBoard` validé par zod), `apps/web/src/app/app.tsx` (rendu selon la route), `apps/web/src/main.tsx` (monte `Router`).
- Code technique : dépendance `zod` dans `apps/web` (MIT) pour valider la réponse HTTP ; ADR-0012 sur le routage client sans dépendance.
- Code de test :
  - Intégration : `apps/server/test/boards.int.test.ts` (`201` avec métadonnées, nom trimé, nom vide ou trop long `400` `VALIDATION_ERROR`).
  - Unitaire : `apps/web/src/app/routes.test.ts` (`parsePath`, `navigate`), `apps/web/src/lib/boards-api.test.ts` (`createBoard` avec `fetch` simulé).
  - E2E : `e2e/create-board.spec.ts` (clic sur « Nouveau board », board « Board sans titre », navigation `/b/<id>`, canvas vide).
- Documentation et Markdown : `docs/architecture.md` (routage client), `docs/adr/0012-routage-client-sans-dependance.md`, `docs/adr/README.md`, `docs/journal.md`, `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F01-S1.md` (étape 1).
- Terminée quand : le test e2e passe et `pnpm verify` est vert.
