# Plan : F01-S1 Créer un board et l'ouvrir

- Ticket : [backlog](../backlog.md), story [F01](../features/F01-gestion-des-boards.md#f01-s1--créer-un-board-et-louvrir)
- Critères d'acceptance visés : F01-S1-AC1, F01-S1-AC2, F01-S1-AC3
- Branche : `feat/F01-S1-create-and-open-board`

## Synthèse des étapes

| N° | Nom | Description | Critères d'acceptance |
|---|---|---|---|
| 1 | API de création de board | Route `POST /api/boards` avec validation zod du nom (1 à 100 caractères après trim), réponse `201 Board` ou `400 VALIDATION_ERROR`. | F01-S1-AC2 : création via l'API ; F01-S1-AC3 : validation du nom |
| 2 | Front : créer et ouvrir un board | Routage client minimal (`/`, `/b/:id`), page d'accueil avec le bouton « Nouveau board », page board vide, appel `POST /api/boards` puis navigation vers `/b/<id>`. | F01-S1-AC1 : création depuis l'accueil et entrée dans le board |

## Étapes

### Étape 1 : API de création de board

- Critères d'acceptance couverts : F01-S1-AC2, F01-S1-AC3
- Code applicatif : `apps/server/src/http/boards.ts` (schéma zod du corps, handler, enregistrement des routes), `apps/server/src/app.ts` (montage des routes quand la configuration fournit une base).
- Code technique : aucun.
- Code de test : `apps/server/test/boards.int.test.ts` (intégration, serveur réel en mémoire) : création `201` avec `id`/`name`/`createdAt`/`updatedAt`, nom vide `400`, nom de plus de 100 caractères `400`, code `VALIDATION_ERROR`.
- Documentation et Markdown : rapport `docs/test-reports/F01-S1.md` (étape 1). L'architecture liste déjà `POST /api/boards` : aucune modification. Journal si une décision est prise.
- Terminée quand : les tests d'intégration de la route passent et `pnpm verify` est vert.

### Étape 2 : Front, création et ouverture d'un board

- Critères d'acceptance couverts : F01-S1-AC1
- Code applicatif : `apps/web/src/app/routes.ts` (type `Route`, `parsePath`, `navigate`), `apps/web/src/app/router.tsx` (hook `useRoute`), `apps/web/src/app/board-list-page.tsx` (bouton `board-create`), `apps/web/src/app/board-page.tsx` (canvas vide `board-canvas`), `apps/web/src/lib/boards-api.ts` (client `createBoard` validé par zod), `apps/web/src/app/app.tsx` (rendu selon la route), `apps/web/src/main.tsx` (monte `Router`).
- Code technique : dépendance `zod` dans `apps/web` (MIT) pour valider la réponse HTTP ; ADR-0012 sur le routage client sans dépendance.
- Code de test : `apps/web/src/app/routes.test.ts` (unitaire), `apps/web/src/lib/boards-api.test.ts` (unitaire, `fetch` simulé), `e2e/create-board.spec.ts` (e2e : clic sur « Nouveau board », board « Board sans titre » créé, navigation `/b/<id>`, canvas vide).
- Documentation et Markdown : `docs/architecture.md` (module de routage), `docs/adr/0012-routage-client-sans-dependance.md`, `docs/adr/README.md`, `docs/journal.md`, `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F01-S1.md` (étape 2).
- Terminée quand : le test e2e passe et `pnpm verify` est vert.
