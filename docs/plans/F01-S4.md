## Étapes

### Étape 1 : supprimer un board depuis le menu

- Critères d'acceptance couverts : F01-S4-AC1, F01-S4-AC2, F01-S4-AC3, F01-S4-AC4, UI-MENU-6, UI-ERR-2
- Code applicatif :
  - `apps/web/src/lib/boards-api.ts` : `deleteBoard` (appelle `DELETE /api/boards/:id`).
  - `apps/web/src/components/ui/alert-dialog.tsx` : composant `alert-dialog` (primitives Base UI, sur le modèle de `dialog.tsx`).
  - `apps/web/src/app/delete-board-dialog.tsx` : `DeleteBoardDialog` : confirmation « Supprimer « <nom> » ? », boutons `delete-cancel` (Annuler, focus initial) et `delete-confirm` (destructif), Échap annule.
  - `apps/web/src/app/board-list-page.tsx` : le bouton `board-delete` ouvre le dialogue ; `BoardListPage` appelle l'API puis retire le board de la liste (ou conserve tout en cas d'annulation ou d'échec).
  - `apps/web/src/app/board-deleted.tsx` : `BoardDeleted` : dialogue modal `board-deleted` « Ce board a été supprimé » avec le bouton `nav-boards`, non fermable autrement.
  - `apps/web/src/collab/use-board-connection.ts` : sur l'événement `close` du provider, vérifie que le board existe encore (`GET /api/boards/:id`) et expose `isDeleted`.
  - `apps/web/src/app/board-page.tsx` : `BoardView` superpose `BoardDeleted` quand la connexion signale un board supprimé.
- Code technique : aucun : le serveur expose déjà `DELETE /api/boards/:id` et la fermeture des connexions (T-003).
- Code de test :
  - Unitaire : `apps/web/src/lib/boards-api.test.ts` (`deleteBoard`), `apps/web/src/app/board-list-page.test.tsx` (contrôle de suppression ; test hérité adapté au nouveau prop `onDelete`).
  - Intégration : `apps/server/test/boards.int.test.ts` (`DELETE` → `GET` 404 ; suppression du document Yjs d'un board pré-rempli via `POST /api/test/seed`).
  - E2E : `e2e/board-delete.spec.ts` (F01-S4-AC1, AC2, AC4), `e2e/layout/board-delete.spec.ts` (UI-MENU-6, UI-ERR-2).
- Documentation et Markdown : `docs/journal.md` (décisions et modification du test hérité), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F01-S4.md` (étape 1). `docs/architecture.md` documente déjà `DELETE /api/boards/:id`.
- Terminée quand : `pnpm verify` est vert (y compris `ac:check` sur F01-S4-AC1 à AC4, UI-MENU-6 et UI-ERR-2), la suppression confirmée retire le board de la liste et rend `GET` 404, l'annulation et Échap conservent le board, et un board supprimé pendant qu'un utilisateur l'utilise affiche le message modal.
