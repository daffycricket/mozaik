## Étapes

### Étape 1 : supprimer la sélection

- Critères d'acceptance couverts : F08-S1-AC1, F08-S1-AC2, F08-S1-AC3
- Code applicatif :
  - `apps/web/src/tools/shortcuts.ts` : `useDeleteShortcut(doc)` écoute `Delete` et `Backspace`, ignore l'événement pendant l'édition d'un texte (champ focalisé ou `editingId`) et sans sélection, puis supprime la sélection via `deleteElements` (déjà fourni par `packages/model`, une transaction à origine locale) et vide la sélection locale.
  - `apps/web/src/canvas/board-canvas.tsx` : active `useDeleteShortcut(doc)`.
- Code technique : aucun : `deleteElements` et l'infrastructure de raccourcis existent déjà.
- Code de test :
  - Unitaire : `apps/web/src/tools/delete-shortcut.test.tsx` (`[F08-S1-AC1]` Suppr et Retour arrière suppriment la sélection, sans sélection rien ne change ; `[F08-S1-AC2]` un champ focalisé n'entraîne aucune suppression).
  - E2E : `e2e/delete.spec.ts` (`[F08-S1-AC1]` suppression d'une sélection de 3 éléments avec Suppr puis Retour arrière ; `[F08-S1-AC2]` Retour arrière pendant la saisie efface un caractère sans supprimer l'élément).
  - Fluidité : `e2e/fluidity/delete.spec.ts` (`[F08-S1-AC3]` mesure FL-1 sur un board de 300 éléments avec 300 ms de latence).
- Documentation et Markdown : `docs/architecture.md` (flux « Suppression »), `docs/journal.md` (décision : sélection vidée après suppression ; test de fluidité), `docs/backlog.md` (statut `done`), rapport `docs/test-reports/F08-S1.md` (étape 1).
- Terminée quand : `pnpm verify` est vert (y compris `ac:check` sur F08-S1-AC1 à AC3) ; une sélection de trois éléments disparaît du document avec Suppr ou Retour arrière, Retour arrière pendant l'édition efface un caractère sans supprimer l'élément, et la suppression reste sous 150 ms sur un board de 300 éléments avec 300 ms de latence.
